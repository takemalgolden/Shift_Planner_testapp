# 月間シフト作成アプリ（試作版）

## できること
- 従業員登録（merchant / consumer / PP の複数スキル）
- 勤務パターンの追加・編集・削除（使用中のパターンは履歴保護のため無効化）
- 曜日・時間帯・スキル別の必要人数設定（追加・編集・削除）
- 休暇・休み希望の手入力とCSV取込（列の対応付け）
- 月間シフトの簡易自動生成（初期版のヒューリスティック）
- 必要人数不足・休み希望未反映の警告
- 警告確認→理由入力→最終確定の二段階確認（同一管理者）
- CSV出力、手動シフト編集、パスワード変更
- SQLiteを使用。外部DB不要。

## 初期ログイン
- 管理者ID: `admin`
- 初期パスワード: `Admin123!`
- 初回ログイン後、必ずパスワードを変更してください。
- 登録した従業員の初期IDは `op{従業員ID}`、初期パスワードは `ChangeMe123!` です。運用前にパスワード変更を必須にする運用を行ってください。

## 起動（試作版）
1. Windows 11 の管理者PCに Python 3.11 以上をインストールします。
2. `run_local.bat` を実行します。初回はFlaskをインストールします。
3. 管理者PCのブラウザで `http://127.0.0.1:5050` を開きます。

## 社内LANで試す場合
1. 管理者PCで `ShiftPlannerServer.exe` を起動します（LAN待受は5050番ポートです）。
2. 管理者PCで `管理者PCで実行_従業員用ショートカット作成.bat` を実行します。`シフト管理.url` が作成されます。
3. `シフト管理.url` を従業員PCへ配布し、ダブルクリックしてアクセスします。リンク先は `http://管理者PCのコンピューター名:5050/` です。従業員がIPアドレスを手入力する必要はありません。
4. 管理者PC自身で確認する場合は `http://127.0.0.1:5050` を開きます。
5. PC名で接続できない場合は、社内ネットワークが名前解決に対応していない可能性があります。社内IT担当者に内部DNS名の設定を相談してください。
6. Windows Defender ファイアウォールの受信規則は、会社のIT担当者の許可を得て、社内LANに限定して設定してください。インターネットへポート公開しないでください。

## 大切な注意
これは業務導入前の試作版です。自動作成は簡易方式で、厳密な最適化ソルバー（OR-Tools等）はまだ組み込んでいません。必要人数を満たすことを保証しません。生成後は必ず「警告確認」で検証してください。
- 必要人数の初期値は各曜日・各スキルで09:20〜23:00に1人として入っています。これはサンプル値です。実際の必要人数・時間帯に合わせて管理画面から修正してください。
- 初期版では「1日につき1勤務パターン・1担当スキル」です。勤務中のスキル切替を時間帯ごとに設定する画面は未実装です。
- 勤務時間、契約日数、連勤上限、勤務可能パターン等は基本的な項目のみです。すべての雇用契約条件を網羅していません。
- Excelファイルを直接読み込む機能ではなく、CSV UTF-8の取込です。Excelから「CSV UTF-8」で保存して取り込んでください。
- 本番運用前に、バックアップ・復元、複数PC同時利用、認証、ログ、アクセス権限、HTTPS、エラー時の動作をテストしてください。
- SQLiteファイル `shift_planner.db` はサーバーPC内に置いてください。共有フォルダー上のSQLiteを複数PCから直接開かないでください。
- `app.py` のセッション秘密鍵は試作用です。本番運用前に環境変数 `SHIFT_APP_SECRET` を十分にランダムな値へ変更してください。

## 休憩時間配置アプリとの連携・希望休提出（追加機能）

1. 休憩時間配置アプリを管理者PCで起動します。
2. シフト作成アプリを起動し、管理者アカウントでログインします。
3. 上部メニューの「従業員データ連携」を開きます。
4. 休憩時間配置アプリの `callcenter.sqlite3` のフルパスを指定し、「従業員を同期」を押します。
   - ソース版の標準パス：`callcenter_local_app/data/callcenter.sqlite3`
   - EXE版の標準パス：`%LOCALAPPDATA%\\CallCenterLocal\\data\\callcenter.sqlite3`
5. 同期されたオペレーターは、休憩時間配置アプリと同じログインID・パスワードでシフト作成アプリにログインできます。
6. オペレーターは「希望休を提出」から希望日を申請し、管理者は「希望休管理」から承認・却下できます。

### 連携の仕様と注意

- 従業員の氏名・在籍状態・スキル・ログインIDをシフト作成側へ同期します。元アプリのDBは読み取り専用で扱い、書き換えません。
- パスワード認証は休憩時間配置アプリのDBで行います。連携アカウントのパスワード変更は休憩時間配置アプリ側で行ってください。
- 元アプリでオペレーターを追加・無効化した場合は、シフト作成側で再同期してください。
- 元アプリでパスワードを変更した場合も再同期は不要ですが、ログイン認証時に元アプリのDBへアクセスできる必要があります。
- 両アプリは引き続き別々のSQLite DBを使用します。DBファイルを同時に直接共有する構成ではありません。
- 希望休の提出と審査は実装されています。既存のシフト生成ロジックでは、承認済みの「有給休暇」「確定休」を割当対象外として扱い、その他の希望は警告・参考情報として扱います。業務ルールに合わせて本番運用前にテストしてください。


## カレンダー上の警告・確定ポップアップ
管理者が「警告・確定」を押すとカレンダー上に警告一覧と二段階確認が表示されます。休憩時間配置アプリ本体はこの配布ZIPに含みません。連携する際は別途そのアプリのSQLiteファイルを指定してください。
